# MVP 开发基线与范围

版本：1.0｜日期：2026-09-19｜状态：可据此拆分开发任务；尚未实现或通过验收。

## 1. 目标与假设

交付一个可演示、可评价的流程：**创建研究项目 → 上传 PDF / 按 arXiv ID 导入 → 分析文献 → 查看主题与争议候选 → 检索证据 → 生成综述 → 人工编辑与核验 → 导出 Word 草稿。**

用户已确认 Python 后端、普通电脑、首期全部模型调用使用 DeepSeek API，整个项目 8 个月交付。本包将 MVP 安排在前 4—6 周，属于 8 个月计划的首个里程碑；这是规划估算，需按实际投入校准。

为便于立即开工，本包采用以下实施默认值，而非声称它们已逐项得到用户确认：

- 单机构内部试用，账号由管理员创建；每个项目归一名用户所有，无项目共享和实时协作。
- 单项目最多 30 篇论文，分析至少 2 篇；以英文文本型论文、中文综述为启动样本，支持中文文本试验但单列质量结果。
- 每个 PDF 最大 25 MiB、50 页；不接受加密 PDF；复杂页通过 DeepSeek 图像能力辅助处理，无法识别时显式失败。
- 标准综述风格，五类固定章节；目标总长度 2,000—4,000 中文字符，属于生成目标而非绝对承诺。
- 每项目同时最多一个活跃后台任务，整个部署初始最多 2 个并发 DeepSeek 请求。等待页面轮询任务，不使用 WebSocket。
- 全部导出标明“AI 辅助生成草稿，需人工审阅”。MVP 不提供直接投稿或自动发布。

这些默认值可在首次开发会议调整；调整接口、字段或状态时必须同步全包文档与契约测试。

## 2. 开发技术基线

| 层 | MVP 基线 | 冻结要求 |
| --- | --- | --- |
| 后端 | Python 3.12、Django 5.2 LTS、Django REST Framework | 采用相容的补丁版本，首次构建记录完整依赖锁文件 |
| 业务数据库 | PostgreSQL | 所有开发和集成测试使用同一主版本；版本在首次构建锁定 |
| 后台执行 | Celery + Redis；独立 worker 与定时调度进程 | 数据库保存真实任务状态，Redis 只用于队列 / 临时协调 |
| PDF | pypdf、pypdfium2 + DeepSeek 图像辅助识别 | 保存原页与证据；CPU 处理，渲染不在线程中无保护并发 |
| 检索 | scikit-learn TF-IDF + 关键词 + DeepSeek 重排 | 不接入向量数据库或第二家模型 API |
| 模型 | DeepSeek，首选验证 `deepseek-flash` | 服务地址、型号、思考配置可配置；上线前完成账户内真实冒烟测试 |
| 前端 | Vue 3 + TypeScript，PDF.js 查看原文 | 沿用已有参考方案；与后端同域发布，开发代理转发 `/api` |
| 导出 | python-docx | 固定模板、可编辑正文、参考文献与证据附表 |

Django 5.2 是 LTS 并支持 Python 3.12，见[官方发行说明](https://docs.djangoproject.com/en/5.2/releases/5.2/)。模型能力依据[DeepSeek 官方文档](https://api-docs.deepseek.com/api/create-response/)，须在实际接入时再次验证；本包没有执行付费请求。

## 3. MVP 范围与暂缓项

| 需求 | MVP | 后续完整项目 |
| --- | --- | --- |
| 文献获取 | 本地 PDF、1—10 个 arXiv ID 批量导入，导入真实元数据与 PDF | 关键词 / 分类 / 时间范围自动搜索、多数据源 |
| 解析与证据 | 按页文本、复杂页图片辅助、正文 / 表格 / 公式 / 图注元素，页级回看 | 精确版面坐标、复杂跨页表格、广泛扫描件质量优化 |
| 语义理解 | 核心要素、带证据单篇摘要 | 扩大领域与语言 |
| 检索 | TF-IDF 召回、查询扩展、DeepSeek 重排 | 预训练语义向量及其研究实验 |
| 主题与争议 | 模型主题归纳、多主题归属、条件对齐、候选人工确认 | 高质量聚类与质量加权实验 |
| 学术质量权重 | 不抓取被引 / 期刊 / 作者指标，不用模型猜测这些数据 | 有来源指标、缺失策略和偏差评价 |
| 趋势 | 纳入语料按年份的数量统计，年份缺失单列 | 学科级趋势及敏感性研究 |
| 生成 | 五类章节、证据 ID 绑定、人工修订、重新核验、Word 导出 | 多风格 / 模板、更多导出格式 |
| 产品工程 | 登录、项目隔离、持久任务、取消 / 重试、预算、失败说明 | 团队空间、实时协作、大规模调度 |

MVP 验收不等于原申请书全部指标完成。特别是预训练语义向量、质量加权与跨模型家族实验仍在后续研究范围；原开发计划保留。

## 4. 唯一术语与标识

- `Project`：研究项目，所有数据均按项目和所有者授权。
- `Paper`：一份不可变 PDF 对应的文献；MVP 不支持原位替换文件。重新上传不同文件形成新文献，旧文献可取消纳入或从当前账本逻辑删除；历史证据保留。
- `AnalysisRun`（简称 Run）：一次冻结研究问题、语料、元数据和配置的分析快照。
- `RunPaper`：Run 中的文献快照，记录纳入时的标题、作者、年份、文件哈希与解析结果。
- `ParsedDocument` / `EvidenceChunk`：解析产物与证据片段；片段 ID 稳定绑定某版解析产物。
- `PaperAnalysis` / `Topic` / `Dispute`：单篇要素与摘要、主题、争议候选，均属于 Run。
- `RetrievalResult`：一次检索的查询、候选与重排证据。
- `Review` / `ReviewRevision`：综述及其不可变正文版本；编辑保存创建新版本。
- `ValidationReport`：对某个正文版本的结构和语义核验，不能复用于修改后的正文。
- `Export`：固定正文版本和核验报告的导出记录。
- `Job`：异步执行记录；Celery task ID 不是公开的业务 Job ID。
- `ModelCall`：单次供应商调用的状态与用量；`FileAsset`：受权限控制的文件记录。

业务 ID 均为 UUID 字符串；内置 Django User 的 ID 对外转换为字符串，不假设是 UUID。外部 arXiv ID 单独保存。JSON 使用 `snake_case`；时间为带 `Z` 的 UTC ISO 8601；页面使用 **1 起始 `page_number`**。

## 5. 版本与状态约束（其他文档必须遵守）

### 5.1 版本

- `Project.version`：可编辑项目字段的乐观锁，从 1 起；PATCH 带 `expected_version`。
- `Project.corpus_revision`：研究问题、纳入集合、文献元数据、删除或恢复变化时递增；未删除文件的重复上传不递增。
- `Paper.version`：元数据、`included` 编辑与删除的乐观锁；删除和恢复也递增。
- `AnalysisRun.corpus_revision`：创建时冻结；`is_stale` 由其与当前项目比较得到。旧 Run 可看，但不允许新生成或新检索。
- `AnalysisRun.analysis_revision`：初始 1；人工调整争议复核后递增。已生成综述记录对应值，变化后显示结果已过时。
- `Dispute.version`：人工复核乐观锁；自动分类保留，人工状态独立。
- `ReviewRevision.revision_number`：从 1 起连续递增，正文不可原位更新。保存时用 `base_revision_number` 防覆盖。
- `ReviewRevision` 冻结 `run_id`、`analysis_revision` 和配置；`ValidationReport`、`Export` 必须指向确切 revision ID。

### 5.2 状态

| 对象 | 唯一状态枚举 |
| --- | --- |
| Job | `queued`、`running`、`cancelling`、`succeeded`、`failed`、`cancelled` |
| AnalysisRun | `processing`、`ready`、`failed`、`cancelled` |
| RunPaper | `pending`、`processing`、`ready`、`failed` |
| Dispute.classification | `possible_conflict`、`different_conditions`、`complementary`、`insufficient_evidence` |
| Dispute.review_status | `pending`、`confirmed`、`rejected` |
| ValidationReport.result | `passed`、`needs_review`（仅已完成的报告；执行失败放在 Job） |
| Export.status | `pending`、`ready`、`failed`、`cancelled` |

Job.kind：`import_arxiv`、`analyze`、`retrieve`、`generate_review`、`validate_review`、`export_docx`。

在项目存在 `queued/running/cancelling` Job 时，新的后台任务，以及项目、文献、争议、正文的修改均返回 `409 PROJECT_BUSY`。取消、查询和相同幂等键的重放例外。事务内锁 Project 行，保证跨请求串行约束。历史文件读取不加写锁。

## 6. 统一接口原则

- 根路径 `/api/v1`，路由统一 **无末尾斜杠**。
- Django Session Cookie 认证；同域请求带 Cookie。所有写请求（包括登录）验证 CSRF；`GET /auth/csrf` 返回令牌并设置 cookie，登录后再次获取令牌。未登录统一 401（实现需覆盖 DRF 默认差异），越权资源统一 404。
- JSON 成功：`{"data": ..., "meta": {"request_id": "..."}}`；列表 `data` 为数组，`meta` 增加 `page/page_size/total`。
- JSON 错误：`{"error":{"code":"...","message":"中文提示","details":{},"retryable":false},"meta":{"request_id":"..."}}`。
- 异步受理 202：`data={"job_id":"UUID","resource_type":"analysis_run|retrieval_result|review|validation_report|export|import_batch","resource_id":"UUID"}`；`import_batch` 的 `resource_id` 使用首次受理的 Job ID，重试沿用此 ID，最终逐项结果通过当前 Job 查询。
- 创建即时资源 201，查询 / 编辑成功 200；文件下载成功返回原始二进制，失败返回标准 JSON 错误。
- 列表 page 从 1 起，page_size 默认 20、最大 100。仅接受已列明过滤参数和字段。
- 所有触发后台任务的 POST 以及 PDF 上传要求 `Idempotency-Key` UUID。作用域为用户 + HTTP 方法 + 规范化路径 + key；请求体（上传含文件 SHA256）不一致返回 409。保留至少 7 天；重放已受理请求返回原受理响应，不重新执行。幂等查找先于 PROJECT_BUSY 检查。
- PATCH / 正文保存拒绝未知字段；None 用 JSON `null`，缺失与空串区别处理；所有对象引用验证归属和 Run 范围。

## 8. 正文与引用格式

`ReviewRevision.sections` 是长度 5 的有序数组；section_key 固定为 `background`、`directions`、`representative_work`、`disagreements`、`trends`。各节含 `title`、`blocks`。

每个 block 包含 `block_id`（UUID）、`kind`（`claim|transition`）、`text`、`evidence_ids`（UUID 数组）。每个 claim 聚焦一个可核对论断，至少 1 个来自当前 Run 的 evidence ID；transition 不应包含外部事实性断言。正文不嵌入模型编造的 `[1]` 文献编号。

生成时由后端分配 block UUID；编辑时已有 block 沿用 ID，新 block 由前端生成 UUID，同一版本不得重复。后端验证文本、引文 ID 和所属关系，禁止传 HTML。编辑保存后必须重新核验；前端负责提示未保存改动。

导出按正文首次引用顺序确定文献编号，从 RunPaper 的冻结元数据生成条目；引用编号和参考文献由后端统一渲染。证据可定位到页面，MVP 不保证句子高亮坐标。

## 9. 故障与验收底线

- 分析时任一纳入论文处理失败，则 Run 为 failed，保留成功阶段产物；用户重试或排除失败论文后新建 Run。不得悄悄跳过失败论文并显示全部成功。
- arXiv 批量导入逐项提交；有任一失败则 Job failed，但成功导入保留并逐项展示。逐项账本初始 pending，下载前保存解析后的具体版本；重试补 pending/failed 项并沿用已解析版本，使用唯一约束避免重复。
- 每项目后台操作事务串行；网络调用在事务外执行。取消合作式生效，已经发出的供应商请求可能产生费用。
- 验证结构错误时正文不能保存 / 生成提交；语义不支持或不确定产生 `needs_review` 报告，允许带明确警示导出草稿。无核验报告不允许导出。
- 冻结测试语料、失败样例和标注标准，使用模拟供应商测试接口，最终另做真实 DeepSeek 小规模冒烟与 👤 学术评审。

## 10. 契约优先级

本包是 MVP 实现规范；旧技术路线用于背景和完整项目路线。包内 `00` 定义范围和跨模块规则，`03` 定义外部 HTTP 字段，`02` 定义持久化约束，`04` 定义流程与内部调用。发现冲突必须更新相关文档后合并代码，不能让不同开发者自行采用不同版本。

这是一套设计交付物，不包含应用实现代码、数据库迁移或部署结果。所有后续任务均从待开始登记。
