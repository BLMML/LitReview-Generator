### 关键路径与并行安排

关键路径：`M01 → M03 → M04/M05 → M06 → M07 → M08/M09 → M10 → M11 → M13 → M14/M15 → M16`，其中 `/` 表示两项都要满足，非二选一。

- M02 与工程骨架并行；前端依据 03 的固定样例先行，不自行发明字段或状态。
- M04 与上传表单、数据库模型可并行设计；arXiv 后台接入依赖 M04 的实际任务底座。
- M08、M09 可共享已冻结证据后并行；M10 必须采用真实 Run 边界，不能长期依赖手写演示数据。
- 每周演示可执行流程：第 1 周登录和项目 → 第 2 周论文与证据 → 第 3 周分析检索 → 第 4 周生成编辑导出 → 第 5—6 周质量与故障修复。
- 每次合并检查契约变更、迁移影响和测试证据。接口破坏性改动同步更新 00—04 和前端，禁止只改一份文档。

## 3. 每项任务的完成定义

1. 实现落在 01 规定的模块边界，字段、错误格式和状态与 00 / 02 / 03 / 04 一致。
2. 正常路径和本模块有实际风险的失败路径通过验证；不为低影响文本变化编写机械测试。
3. 后端在服务端完成授权、归属检查、并发检查和输入校验；前端校验仅用于交互提示。
4. 数据库迁移可在空库和上一版数据上执行；影响持久化时说明升级与回滚方案。
5. 日志可从 request_id 关联到 Job / Run / ModelCall；不含 API Key、会话 Cookie 或不必要的论文全文。
6. 评审人能按记录复现结果，提交记录、测试结果、缺陷链接和必要截图 / 导出样本可追溯。

## 4. 必须覆盖的质量与故障矩阵

以下 HTTP 路径均省略 `/api/v1`。供应商替身必须复现请求结果和异常，不让日常自动测试产生付费调用；最终真实冒烟单独登记。

| 编号 / 层级 | 场景 | 必须证明的行为 |
| --- | --- | --- |
| T01 API | 登录、退出、CSRF | 先 GET `/auth/csrf`，POST `/auth/login` 后重新取令牌；缺失 / 错误 CSRF 的写请求被拒绝，含登录；未登录统一 401，退出后会话失效。 |
| T02 API / 文件 | 两用户和伪造对象引用 | 跨用户查询、修改、Job、证据、PDF、导出均 404；不存在通过猜 UUID 或文件路径读取他人数据的入口。 |
| T03 文件 | 上传边界与恶意文件 | 25 MiB、50 页边界按 00 执行；超限、加密、损坏、扩展名伪装、路径穿越文件名、渲染失败均可解释拒绝；临时文件清理，不执行文档内容。 |
| T04 集成 | arXiv 批次与去重 | 限定 ID 导入，不接受任意 URL；部分成功保留，任一失败 Job failed；重试仅补失败项，不生成重复文献；外部请求设超时和下载大小限制。 |
| T05 API / 数据库 | 幂等与并发重放 | 同 key 同请求返回原受理响应；同 key 改内容冲突；文件哈希参与比较；活跃任务下同 key 重放仍成功；两请求竞争只产生一个受理结果。 |
| T06 事务 | 项目串行和队列故障 | queued / running / cancelling 期间其他后台任务及规定的编辑返回 PROJECT_BUSY；项目行锁有效，网络请求不占数据库事务；提交后入队失败可恢复，不产生孤儿任务。 |
| T07 任务 | 取消与重试 | queued、running、终态分别验证；取消合作式生效；重试创建新 Job、关联原资源，不覆写旧 Job 历史；陈旧 Run 的分析 / 检索 / 生成重试返回 STALE_RUN。 |
| T08 任务 / 模型 | 供应商异常与格式校验 | 覆盖限流、5xx、超时、空输出、截断、畸形 JSON、缺字段、未知枚举、伪造证据 ID；有限次重试和可解释失败，不以自由文本兜底提交成功。 |
| T09 解析 / 集成 | 页级证据与解析失败 | 抽检页码、文本和源文件一致；模型辅助识别标注来源与不确定项；越页 / 越 Run 证据不通过；任一纳入文献失败使 Run failed，账本记录全部结果。 |
| T10 数据库 / API | 快照与 stale | 改研究问题、纳入集合或元数据后 corpus_revision 递增；旧 Run 仍可读但不能新检索 / 生成；重复同文件不递增；RunPaper 的历史标题、年份和哈希不随编辑变化。 |
| T11 API / 数据库 | 编辑乐观锁与核验失效 | Project、Paper、Dispute 的过期 version 被拒绝；双端基于同一正文版本保存只接受一个；新修订不可复用旧报告；争议复核递增 analysis_revision，历史综述显示过时。 |
| T12 API / 导出 | 警示和版本绑定 | POST `/reviews/{id}/exports` 的 revision_id、validation_id 必须相匹配；无完成报告或 structure_passed=false 不导出；needs_review、stale 或历史正文须 acknowledge_warnings=true，并在 Word 标明警示。 |
| T13 预算 / 模型 | 并发、费用和超时 | 全部署最多 2 个并发模型请求；预算预留原子化；实际已知用量据实结算，超时 / 取消的未决费用可追踪，不直接记零或立即全部释放；不足时拒绝后续新调用。 |
| T14 安全 / 模型 | 文献内提示注入 | 论文含“忽略规则”“输出密钥”“调用网址”等文本时，仍只当资料处理；模型无自行抓取任意 URL / 读文件 / 执行命令权限；输出只可引用允许证据集合。 |
| T15 恢复 / 集成 | worker、Redis 和进程中断 | 在入队、调用后、写结果前后杀进程；恢复后无永久 running、重复正文或重复导出；数据库是任务真相源，缓存 / 队列故障不会丢业务状态；未决模型调用不盲目重复。 |
| T16 端到端 | 最短完整流程 | 用至少 2 篇真实论文完成登录到 Word；所有 claim 结构合法、引用可回看、编辑创建新版本、导出固定版本；演示数据不能绕过正式服务层。 |

测试分层：纯规则 / 校验做单元测试，事务与约束做 PostgreSQL 集成测试，路由和错误做 API 契约测试，跨页面关键路径做端到端验证。不得仅用 SQLite 通过结果证明 PostgreSQL 并发约束正确。

补充关键断言：T01 对匿名登录缺失 CSRF 同样要求 403；T07 验证 J1 失败、J2 成功后再次重试 J1 被拒绝，导入重试保持原 import_batch resource_id；T12 验证导出失败后新增 stale / 历史版本警示时，旧确认不能覆盖新警示，必须新建并确认 Export；T16 刷新页面后通过历史列表找回正文版本、核验报告、检索、导出和失败导入任务。human_verified 本期为保留枚举，不能通过未定义接口或模型自评设置。

T04 还需验证取消 / 中断留下的 pending 项能在重试继续，resolved_source_id 下载前已经保存且重试不漂移到新版本；T10 历史页显示 Run 的冻结研究问题；T16 在旧 Run 中通过论文页级证据列表选择未被检索命中的引文，并保存新修订，不额外强制发起模型检索。

## 5. 学术质量与性能验收

### 5.1 建立冻结评测包

- 建议启动样本 20—30 篇，满足 MVP 文档限制，包含普通论文、表格 / 公式 / 多栏难例、条件相似与不同的论文组合；中文文本试验单列，不能混入英文结果后宣称普遍支持。
- 调试集可反复使用；验收集及其标注在最终评估前冻结，生成、重排或提示词调整不得偷看后选择性报告。缺少覆盖时补充样本并重新登记版本。
- 标注至少包括：源页、关键要素、支持 / 不支持的论断、可比条件、争议判定及其理由。两名评审独立判断；分歧由指导教师或指定评审裁决。
- 报告记录样本数、无效样本处理规则、分母、模型 / 提示词 / 配置版本和未解决案例；没有足够样本时写“证据不足”，不能标记通过。

### 5.2 首次会议可采用的建议门槛

下表是待 M02 确认的启动建议，不是已经达到的指标，也不是正式项目承诺。

| 项目 | 建议门槛 / 判定方法 |
| --- | --- |
| 结构与归属 | 被接受的 claim 均有合法、同 Run 的证据 ID；跨用户 / 跨 Run 引用、错误版本导出必须被拒绝。这是程序不变量，不等于学术正确率 100%。 |
| 引文支持率 | 抽样至少 50 个事实性 claim，人工判定充分支持比例建议 ≥90%；分别报告不支持、部分支持、证据不足，禁止仅检查 ID 存在。 |
| 核心要素 | 至少 50 个有明确原文依据的要素字段，正确提取比例建议 ≥85%；原文缺失时正确留空单列，不用大量空值抬高得分。 |
| 检索 | 在冻结问题上报告 Recall@10 与来源页命中率，先建立关键词基线；候选语料很小或标注不全时不宣称通用召回率。数值门槛经基线后冻结。 |
| 争议候选 | 对至少 20 组专家可判定组合评估，兼含真正冲突与条件不同；“possible_conflict”建议精确率 ≥80%，同时报告召回率与误报例。样本不足则仅开放待人工复核展示。 |
| 处理账本 | 所有纳入文献都有处理状态；失败明确可见，不以静默跳过实现成功率。 |
| 资源与体验 | 在目标普通电脑记录内存峰值、每页解析耗时、单次 / 全项目时长、模型请求数与费用；以实测确定容量和等待提示，不预先承诺硬件无关时延。 |

任何新正文均需核验，即使上一个版本已 passed；模型语义核验只是辅助，不能替代人工学术评审。预算采用预留与核算控制，供应商实际计费、未知用量和网络超时可能造成偏差，不承诺毫厘不差的费用封顶。

## 6. 人工 UAT 操作脚本

以下每步保存请求 ID、主要页面截图和预期 / 实际结果；失败建立缺陷，修复后复测相关步骤。

1. **账户与项目**：GET `/auth/csrf` → POST `/auth/login` → GET `/auth/csrf` → POST `/projects`；确认 GET `/auth/me` 和项目列表正确。另一个账号访问项目、PDF 和导出应为 404。
2. **两种接入**：POST `/projects/{id}/papers/upload` 上传至少 2 篇 PDF；POST `/projects/{id}/imports/arxiv` 导入一个成功 ID 和一个格式合法但获取失败的 ID；GET `/jobs/{id}` 查看逐项结果，重试后确认成功项未重复。
3. **元数据与证据**：PATCH `/papers/{id}` 补年份 / 纳入状态；POST `/projects/{id}/runs`，轮询 Job；GET `/runs/{id}` 核对文献账本，GET 单篇 `/analysis` 与 `/evidence/{id}`，在 PDF 原页人工对照。
4. **检索与分析**：POST `/runs/{id}/retrievals`，GET `/retrievals/{id}`；查看 `/topics` 与 `/disputes`，PATCH `/disputes/{id}` 确认或拒绝一项，核对条件和双方证据。
5. **生成与编辑**：POST `/runs/{id}/reviews`；GET `/reviews/{id}` 查看固定五节；POST `/reviews/{id}/revisions` 修改一项，第二窗口使用旧 base_revision_number 保存应冲突。
6. **核验与警示导出**：POST `/reviews/{id}/validations` 后 GET `/validations/{id}`；针对 needs_review / stale / 历史版本检查确认警示流程；POST `/reviews/{id}/exports` 后 GET `/exports/{id}/file`，在 Word 核对正文、编号、证据附表和警示。
7. **陈旧快照与历史**：无活跃 Job 时修改一条文献元数据，旧 Run 应 stale 且禁止新检索 / 生成；旧正文和冻结引文仍可读，历史导出不得偷偷替换成最新元数据。
8. **中断恢复**：启动任务后 POST `/jobs/{id}/cancel`，再按允许条件 POST `/jobs/{id}/retry`；验证新旧 Job 分开记录。执行一次 worker 中断恢复和备份恢复，在恢复环境重新打开论文、正文与导出。

## 7. 缺陷分级与放行

| 等级 | 示例 | 放行规则 |
| --- | --- | --- |
| P0 | 跨账号数据泄露、密钥泄露、原始文件 / 数据不可恢复损坏 | 立即停止试用和新发布，先控制影响；修复并完成相关回归与恢复验证。 |
| P1 | 主流程不可完成、引用串文献、错误正文版本导出、任务永久卡死、失控重复计费 | 发布阻塞；修复后验证正常与失败路径。 |
| P2 | 可绕行的交互问题、非关键统计或提示不完整 | 负责人记录影响、替代操作和修复期限后决定是否试用。 |
| P3 | 不影响功能的排版、文案问题 | 登记后续修复；不因此重复完整学术评估。 |

放行条件：P0 / P1 为零；T01—T16 有结果且关键路径通过；学术建议门槛已确认并满足，或缩小能力声明并经人工签字接受明确限制；完成恢复演练及交接。不能通过隐去失败样本或取消核心证据核验来放行。
