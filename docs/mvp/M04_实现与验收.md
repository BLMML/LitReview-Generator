## 1. 已实现的能力

- 任务：幂等受理、项目级互斥、事务提交后投递、投递失败补偿、进度、取消、重试历史、后台心跳、租约 fencing 与 worker 失联恢复。失联任务结束为 `WORKER_LOST`，不自动重放可能已计费的调用。
- 模型：统一 `call_structured(context, request)`，mock 夹具与真实 DeepSeek Chat Completions 适配器；严格 JSON / Schema / 引用白名单校验，拒绝空响应、截断、非法引用和重复键。
- 重试：按错误类型决定是否重试，上限不超过三次，最多一次结构修复；每次尝试分别记录账本。认证与余额错误直接停止。请求有总时限和响应大小限制。
- 预算：短事务原子预留、部署级数据库并发名额、已知用量结算；费用未知保留 `unsettled` 与预留金额，不写零伪装成功。网络超时的名额保留至安全到期，避免潜在请求重叠。
- 结果：经过校验的业务响应写入私有 FileAsset；缓存包含项目、Run、输入、提示词、模型与 Schema 版本，命中时重验哈希及引用。同一缓存结果不重复扣费。
- 安全边界：图片仅接受同项目私有文件 ID；模型网络请求在数据库事务外；取消和过期租约不能提交领域成功结果；日志不记录密钥、完整原文或推理内容。

领域模块仍须负责证据归属等业务级检查；M05 之后的上传、解析、分析和生成处理器未在本阶段实现。

## 2. 用户已确认的价格契约

快照在每次网络尝试发起前冻结，含六价、模型、配置哈希、价目版本、UTC 日历、档位与时间。后续修改配置不会重算历史请求。官方公布的峰段是工作日 UTC `[01:00,04:00)`、`[06:00,10:00)`，中国法定节假日例外；本实现要求运维通过全谷日期清单核验例外日期。[官方计价说明](https://api-docs.deepseek.com/quick_start/pricing/)

## 4. 后续模块怎么接

受理阶段调用 `accept_job` 并传入幂等 Claim。该服务已经在同一事务记录 202 响应并注册提交后投递；调用方不能再次记录或投递。`AcceptedJob.replayed` 标识幂等重放。

领域 worker 使用有效 `ExecutionContext`，在事务外构造请求并调用网关。例如查询扩展：

```python
from apps.llm.client import call_structured
from apps.llm.prompt_loader import load_prompt
from apps.llm.schemas import ModelTaskRequest

payload = {
    "research_question": "attention",
    "current_query": "attention",
    "domain_context": "learning",
    "max_queries": 3,
}
prompt = load_prompt("expand_query.md", payload, task_type="query_expand")
request = ModelTaskRequest(
    task_type="query_expand",
    template_version=prompt.version,
    schema_version="1.0",
    model_config={},
    payload=payload,
)
result = call_structured(context, request)
```

mock 默认返回受控固定夹具，涉及论文 / 证据的任务必须使用与夹具匹配的白名单，不能把固定结果当成真实语义能力。领域写入仍在短事务内复验租约与资源版本，使用 `record_progress` / `complete_job` 提交进度及终态。
