## 2. 本轮修复规则

### 2.1 快照、项目与执行资格

真实 `RunPaper` 的项目归属从 `run.project_id` 获取。校验论文、快照、原始 FileAsset 的项目、
文件 ID 与 SHA256 一致；传入执行上下文时，项目和冻结 Run 必须匹配。

后台调用使用 `claim_execution()` 返回的真实 `ExecutionContext`。
取消、过期或已被新尝试取代的租约不能发布、提交诊断或写入页面图像。
文本层的 `context=None` 入口保留给受控调试与测试；生产 Run 流水线应传真实上下文，
缺少上下文时不能调用模型。

发布事务持有 Job 行锁到产物与片段提交，并在事务结束前再次检查租约。
PDF 提取、页面渲染和模型网络调用在该短事务外完成。
同一原始 FileAsset 的并发发布通过行锁串行，复用已有完整产物并保持相同证据 ID。

### 2.2 图像按单页调度

PageExtract 的返回结构没有元素页号，因此每次只发送一张页图；
`PAGE_IMAGES_PER_CALL=1` 为默认值，配置中的 2 仍是上限，当前单页策略不超过它。
两个扫描页会产生两次独立调用，后端把各页返回内容绑定到对应真实页号与页图。
保留每个模型元素的 `element_type`、`section` 和原有顺序，表格与公式不再被合并为正文。

此前“整批结果只绑第一页、第二页主动失败”的策略已移除；多页图像测试改为验证两页正确成功。

### 2.3 冻结配置真实生效

有效配置包括 parser / normalization 版本、切片长度、渲染倍率、图片字节上限、
图像数上限、提示词版本、Schema 版本，以及 model / thinking / max_tokens / temperature。
完整配置写入 structured 产物，按同一配置计算 `config_hash`，并将其参数传入切片、渲染和模型网关。
修改有效默认值会生成新产物；传入完整冻结配置时，受支持的原参数继续控制实际输出。

未知字段、不合法范围或当前代码不支持的冻结版本会明确拒绝；
不会用新代码或新提示词生成结果后仍标成旧配置。旧环境恢复或创建新任务由调用方决定。
模型与输出上限仍受 M04 当前已核验的部署与计价配置约束。

### 2.4 证据匹配、顺序与定位

每个片段必须落在实际页数内，`locator={"granularity":"page","bbox":null}`。
文本层片段经空白归一化后，必须能在同页原文中找到，才标为 `text_matched`；
保留该页 `original_text`。页码 999 或虚构文字会失败。

图像转录一律 `image_unverified`、`original_text=null`，绑定真实页图；不自动设置 `human_verified`。
页码之间稳定排序，同页元素保持输入顺序。切片只截取来源文本，不通过重排句子生成新正文。
重复构建相同内容返回原证据 ID；已发布片段不能原位改成不同内容。

文本层 `detect_section` / `element_type_for` 仍是明确形态的启发式判断，不能当作学术语义识别。

### 2.5 缓存完整性与失败清理

命中缓存时校验 raw / structured 文件存在、字节数和 SHA256；
对照配置、版本、页号、页面覆盖与完整片段集合；图像来源文件也需通过完整性检查。
缺文件、损坏产物、缺失片段或篡改证据明确返回 `PDF_PARSE_FAILED`，保留历史记录用于恢复，
不会把损坏缓存当成成功或覆盖旧证据 ID。

暂存、文件登记、ParsedDocument 与片段发布均有失败清理：
第二个暂存失败时清理第一个；第二个文件提交或片段写入失败时，回滚数据库并删除已移入存储但未提交的文件。
诊断产物与页图记录 `source_job`。合法失败页保留诊断 ID 与逐页错误；
若取消或租约已失效，诊断写入同样被拒绝。
