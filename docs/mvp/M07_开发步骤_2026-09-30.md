## 4. 按这个顺序编写代码

### 4.1 分析受理和快照：backend/apps/analysis/services.py

实现 `create_run(actor, project_id, payload, key)` 与 `get_run_snapshot(...)`。

1. POST 创建分析只接受契约规定的空对象；验证项目权限与 Idempotency-Key。
2. 在 Project 行锁内先查幂等重放，再检查忙状态；纳入论文少于两篇返回 INSUFFICIENT_PAPERS。
3. 冻结 research_question、output_language、corpus_revision、论文集合与元数据、FileAsset、哈希、页数。
4. 将 `parsing.config.effective_config()` 的完整结果及单篇抽取的模型、模板、Schema 配置冻结。
   写入 Run.config_snapshot 与任务 frozen_input，不能执行时再读最新默认值替换。
5. 同一事务创建 Run、RunPaper 和 analyze Job；复用 `jobs.services.accept_job` 的幂等、忙状态和提交后派发机制。
6. 重放相同 key 返回原 202 受理结果；不产生第二套 Run、RunPaper 或 Job。

### 4.2 单篇输出验证：backend/apps/analysis/schemas.py

实现 `validate_paper_analysis`。输出必须有以下八个字段：

- research_question、research_object、summary：单个 `{value, evidence_ids}`。
- methods、datasets、metrics、conclusions、limitations：上述结构的数组。

缺失信息为 value=null、evidence_ids=[]；没有数组条目时为 []。
有事实内容必须附合法证据。拒绝未知字段、错误类型、伪造 ID、跨 Run ID 和同 Run 其他论文的 ID。
单篇分析只能使用当前 RunPaper 的证据；模型不能自行指定真实页号或论文归属。

### 4.3 逐篇执行：backend/apps/analysis/services.py

实现 `execute_run(context, run_id)` 的 M07 阶段及内部辅助函数。

1. 检查实际 Job、项目、Run 和租约，读取冻结输入。
2. 逐篇传真实 RunPaper 与完整冻结 parser_config 调用 `parse_paper`。
3. 在持 Job 锁且复查租约的短事务内回填 `RunPaper.parsed_document`。
4. 为当前论文组织 evidence_chunks 和允许引用的 ID，调用 M04 `call_structured` 的 paper_extract 任务。
   `extract_paper.md` 中 page_extract 与 paper_extract 是独立段，不混用。
5. 使用冻结标题、题录、研究问题与证据包；输入超过模型上限时明确失败或实现可追溯分批，不能静默截掉未处理正文。
6. 校验输出和证据归属后，原子保存 PaperAnalysis、generation_snapshot、model_call_ids 与 RunPaper.ready。
7. 任一论文失败记录论文错误并使 Run.failed，保留已完整提交的成功阶段；不得只汇总成功论文。
8. 取消后停止新调用；未完成的 RunPaper 按契约回 pending，Run.cancelled。
   失效或被替换租约不能写业务结果；重试沿用冻结输入，仅复用完整且身份一致的产物。

模型、PDF 和其他网络处理在事务外；资格校验和阶段写入在同一个短事务中。
抽取逻辑可先写在 services.py 的内部函数；需要拆分时**新增** analysis/extractors.py，目前该文件不存在。
