## 2. 关键设计决定

### 2.1 索引只在内存里，不落盘

`01` 第 4.5 节要求"内部索引由服务生成，**不能接收用户上传的 pickle / joblib 对象**"。
最彻底的实现是不引入序列化面：索引在 worker 进程内拟合、进程内缓存，不写文件、
不反序列化。缓存键为 `{run_id}:{analysis_revision}:{index_version}:{document_count}`，
任一变化即重建——因此不存在"读到别人给的索引文件"或"缓存与语料不符"的路径。

代价是每次 worker 重启后首次检索要重建索引。MVP 语料为 30 篇 × 每篇若干片段，
这个代价可接受；换来的是没有索引完整性校验这一整类风险。

### 2.2 向量器必须与矩阵一起保存

`TfidfVectorizer` 的 `fit_transform` 产出的词表**必须**保留：只在查询时重新 `fit`
会得到另一套词表，列索引对不上，余弦相似度会**静默算错**——不抛异常，只是排序离谱。
实现把已拟合的 `vectorizer` 与矩阵一起存进 `_Engine`，并在字段注释里写明原因。

### 2.3 召回是两条路径的融合

- **TF-IDF 余弦**：主分，取各扩展查询上的最大值；
- **关键词覆盖率**：`|query ∩ chunk| / |query|`，乘 0.5 叠加。

第二条不是装饰：短查询或低频术语在 TF-IDF 上可能得 0 分（词不在词表内），
而字面命中恰恰是最可靠的信号之一。融合后按 `(score 降序, matched_queries 数降序,
evidence_id 升序)` 排序，保证同一输入复现同一顺序。

分词不引入额外依赖：英文按连续字母数字切分，**中文按字切分**
（scikit-learn 默认的 `token_pattern` 会整段丢弃中文，必须显式提供 tokenizer）。

### 2.4 越界引用有两道拦截

契约要求"从模型重排结果读取的 evidence ID 必须属于候选集合"。

- **第一道（M04 网关）**：`validate_payload` 按 `request.allowed_evidence_ids` 白名单
  校验 `evidence_id`，越界即 `MODEL_OUTPUT_INVALID`；
- **第二道（服务层）**：`validate_ranked_evidence` 再按实际候选集合校验一次，
  越界即 422 `INVALID_EVIDENCE`。

两道都要有：网关的白名单来自请求参数，服务层的候选集合来自真实召回结果，
后者才是权威。测试用替身**绕过网关**直连服务层，证明第二道确实独立生效。

### 2.5 查询扩展失败不拖垮整次检索

扩展查询结构不合法时**保守退回原查询**（`["原查询"]`），而不是让检索失败。
扩展只是提高召回的手段，不是检索的必要条件；为它失败会让用户看到一个本可避免的错误。

但**扩展列表的第一项必须是原查询**——这是契约要求，也是"扩展没有偷换问题"的证据。

### 2.6 完成前 `results` 为 null，成功但无证据为 `[]`

两者必须可区分：`null` = 还没跑完；`[]` = 跑完了但没有可用证据。
把后者写成 `null` 会让前端一直等下去，把前者写成 `[]` 会谎报"检索完成但没有结果"。

### 2.7 结果与 Job 终态同一事务提交

`jobs.tasks.execute_job` 只负责分发：领域服务不提交终态时它会把 Job 判成
"执行函数未提交终态"并标 failed。因此 `_publish` 用 `complete_job` 的
`finalize_resource` 回调，把 `results` / `candidates` / `expanded_queries` 的写入
与 `Job.succeeded` 放在**同一个事务**里，避免出现"结果已发布、Job 却是 failed"。

### 2.8 逻辑调用 ID 必须稳定

重排的 `logical_call_id` 由**检索记录 ID** 派生，不是随机 UUID。
随机 ID 会让每次重试都变成一次全新的付费调用，既重复计费，也让调用账本失去幂等性。

## 3. 本轮修正的 1 个既有缺陷

### `GET /runs/{id}/retrievals` 从未挂载视图

`retrieval/api.py` 的 `urlpatterns` 只注册了 POST 的 `run_retrievals_create`，
同名的 list 视图 `run_retrievals_list` **没有任何路由指向它**。GET 因此落进 405 兜底分支，
再叠加 `common/http.py` 兜底分支的 `TypeError`（见 M07 记录）变成 500 ——
契约里"用于恢复历史查询"的路径实际不可用。

已合并为一个端点函数同时处理 GET / POST，并为 list 补上 Run 归属校验：
他人的 Run 返回 404，而不是"200 + 空列表"（与 M05 复核中 `project_papers` 同类问题）。

回归由 `test_contract_auth.py::test_documented_get_routes_are_not_method_allowed` 守住，
**必须用已登录请求**：未登录时 401 与 405 都来自 DRF 的方法分发检查，无法区分。
