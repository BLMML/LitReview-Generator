## 2. 核验行为

`POST /api/v1/reviews/{review_id}/validations` 必须提供 `revision_id` 和 `Idempotency-Key`。返回 202；`resource_id` 是核验报告 ID。

受理时冻结正文哈希、提示词版本、Schema 摘要、模型配置、输出语言、批大小、输入上限和引用证据摘要。历史正文与过时 Run 可以核验；不会擅自切换到最新正文或新分析。

默认每批最多 5 个 block。分批时计算完整系统提示词、Schema 和原文的 UTF-8 保守上界，并保留一次格式修复额度；不截断证据。如果单块完整引用仍超过输入上限，任务明确失败，用户需缩减该块引用后保存、重新核验。

每批模型输出必须覆盖输入 block 恰好一次。任务的逻辑调用 ID 由报告 ID 与批次派生，重试沿用；既有网关继续负责调用总次数、费用预留、缓存和 fencing。

| 情形 | 报告 | Job |
| --- | --- | --- |
| 所有事实有支持、结构通过 | `passed`，`structure_passed=true` | succeeded |
| 存在 unsupported / uncertain | `needs_review`，结构检查结果单独保留 | succeeded |
| 节序、引用、HTML、来源文件等结构问题 | `needs_review`，`structure_passed=false`，禁止导出 | succeeded |
| 模型请求失败、输出漏块 / 重复 / 新增 ID | result、structure_passed、blocks 三项保持 null | failed |
| 取消或租约失效 | 不发布完成报告 | 由任务取消或恢复机制收尾 |

所有 transition 也进入语义核验。`not_applicable` 只有在后端能确定为纯承接语时才被接受；含引用或无法确定的承接段保守转为 `uncertain`。无引用的块不能判为 supported。引用未经人工核对的图像转录同样要求人工复核；本期不自动设置 `human_verified`。

## 3. 导出与重试

`POST /api/v1/reviews/{review_id}/exports` 提供同一正文的 `revision_id`、`validation_id` 和 `Idempotency-Key`。报告必须对应成功的核验 Job，结构通过、块覆盖完整、内容及证据摘要一致。

以下警示分别计算并在 Word 中保留：核验 needs_review、Run 语料过时、分析版本过时、导出非最新正文。存在警示时必须显式提供 `acknowledge_warnings=true`，否则返回 409 `WARNINGS_NOT_ACKNOWLEDGED`。

确认只覆盖该次受理时的警示集合。失败导出后来新增过时或历史版本警示时，旧确认不能覆盖新警示；重试返回 409，用户应新建 Export 并确认。允许重试时沿用原资源与冻结输入，旧 Job 的失败历史不改写。

Word 只渲染冻结输入，不再次检索或调用模型。编号按正文首次引用的论文顺序去重；参考文献只使用 RunPaper 快照，未知作者、年份和章节明确显示未知。文件包含五节正文、参考文献、导出警示、逐块待审问题、页级原文证据附录和版本记录；每页页眉标明“AI 辅助生成草稿，需人工审阅”。

文件写入私有暂存目录，关闭后检查 ZIP 完整性及 python-docx 可打开性。发布前再次检查租约、取消、正文、报告、证据和警示；FileAsset、Export.ready 与 Job.succeeded 在同一事务发布。回滚会清理本次未发布的正式文件。失败、取消与租约回收不会产生可下载成功文件。

导出发布与任务终态使用 `Project → Job → Export` 锁序；取消仅需 Job 锁，不通过鉴权 JOIN 锁住 Project。与 M10 生成的 `Project → Review → Job` 链路互不嵌套。

### 5.1 重启服务

分别打开独立 PowerShell 窗口。每个前台服务窗口保持打开；此前 worker 和 Django 已运行的话，先在相应窗口按一次 Ctrl+C，再按下面命令启动。无需重新安装依赖或运行新迁移。

第一个窗口启动本地依赖：

```powershell
cd 'D:\LitReview Generator'
.\.venv\Scripts\python.exe .data\tools\pg_ctl_local.py start
.\.venv\Scripts\python.exe .data\tools\redis_local.py start
```

```powershell
cd 'D:\LitReview Generator\backend'
```

### 5.3 用已有正文走一次 HTTP 流程

需要一个有已保存正文的 Review。`GET /api/v1/reviews/{review_id}` 中 `latest_revision` 不得为 null。没有正文时先完成 M10 生成；此脚本不会伪造 ready Run 或成功正文。

设置你的本地账户，替换下面三个占位值。默认导出最新版；需要历史版本时再加 `--revision 正文版本UUID`。

```powershell
cd 'D:\LitReview Generator'
$env:PYTHONUTF8 = '1'
$env:DEMO_USER = '你的本地用户名'
$env:DEMO_PASSWORD = '你的本地账户密码'
.\.venv\Scripts\python.exe backend\tests\walkthrough_validation_http.py --review '你的ReviewUUID' --acknowledge-warnings
```

`--acknowledge-warnings` 表示你确认这次的待审或历史版本警示。mock 会诚实返回 needs_review，因此模拟流程通常需要此参数。脚本完成后打印 Word 路径，下载文件位于 `.data/m11-exports/`。确认草稿页眉、正文版本、引用编号、原文页码与待审问题。

不使用脚本时按 API 顺序操作：提交 validation → 查询 Job 到 succeeded → 读取报告 → 用同一 revision_id 和报告 ID 提交 export → 查询导出 Job 到 succeeded → 下载 `GET /api/v1/exports/{export_id}/file`。核验或导出未完成时不要拿 job_id 当报告或导出 ID。
