# MVP 开发交付包

**项目：学术文献综述智能生成系统**  
**版本：1.0｜交付日期：2026-09-19｜用途：交给程序员开始实施。**

## 一、先看这页

本包将已讨论方案落实为 **Python 后端 + DeepSeek API** 的 MVP 实现规范，包含文件职责、数据库字段、统一 API、模型输出格式、任务流程及验收任务。

首版跑通：**登录 → 创建研究项目 → 上传 PDF / arXiv ID 导入 → 解析与分析 → 查看原文证据 → 生成五节综述 → 人工修订与核验 → 导出 Word 草稿。**

实施基线为 Django + DRF、PostgreSQL、Celery + Redis、Vue 3 + TypeScript；全部模型调用走 DeepSeek。具体框架、30 篇容量、4—6 周 MVP 节奏等是本包为开工设定的默认值；用户已确认的是 Python 后端、DeepSeek 首期模型平台、普通电脑与整个项目 8 个月交付。首次会议可调整默认值，调整后统一修改契约。

**这些文件是设计文档与接口契约，尚未创建应用代码、部署服务或调用付费 API。** 各任务状态仍为待开始。第一天应依此建仓库、锁依赖、生成迁移和 Mock，再开始模块实现。

## 三、第一批开发工作

1. **负责人组织首次会议**：读 00，登记成员时间、试点论文、预算和部署条件；先确认修改项，不重新发散技术栈。
2. **后端完成基础接口**：配置、数据库迁移、会话 / CSRF、项目隔离、统一响应与错误，建立两个测试用户。
3. **前端同步开发**：以 OpenAPI 和合成样例制作 Mock，先完成登录、项目、上传和任务状态页面；HTTP 字段保持 snake_case。
4. **后端建立持久任务与模型替身**：先验证幂等、项目单任务、取消 / 重试和预算，再接真实 DeepSeek。
5. **文献与模型模块并行推进**：按文件职责实现上传 / 导入、解析 / 证据、单篇分析，再接检索、综述、核验与导出。

第一条真实集成路径先使用 2 篇论文；稳定后扩展至 20—30 篇冻结评测样本。模拟测试与真实学术质量评价分别记录。

## 四、不可分叉的协作约定

- 后端服务与前端使用相同路径、字段、枚举和错误码；变更须同步文档、OpenAPI、类型与测试。
- `Job` 记录任务执行，`Run` 冻结语料，`ReviewRevision` 保存不可变正文；三者不能混用。
- 证据 ID 来自真实解析产物，模型不能自行创建文献、页码或参考文献条目。
- 先检索再生成；首期词频检索加 DeepSeek 重排，预训练语义向量和学术指标加权留在后续完整项目。
- 原始文件与历史正文不覆盖；人工修改生成新版本，必须对新版本重新核验。
- 模型 Key 只在后端，未知用量与失败调用如实记录；不以同一模型自评代替人工评审。
