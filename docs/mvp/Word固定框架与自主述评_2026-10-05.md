# Word 固定研究框架与自主述评

日期：2026-10-05。适用于本次更新后新生成的综述；覆盖 2026-10-03 的旧六槽导出规范。

## 1. 固定正文结构

1. 研究背景
2. 研究思路
3. 研究意义
4. 文献综述
   1. 理论基础
   2. 国内外研究现状
5. 文献述评
   1. 已取得的成果
   2. 文献的不足之处
   3. 本文创新点

后台八槽依次是 background、approach、significance、theoretical_basis、research_status、achievements、limitations、innovation。Word 使用一级标题 1—5、二级标题 4.1—4.2 与 5.1—5.3，编辑页锁定标题与顺序，不增减核心模块。

## 2. 原文模块

前四个主模块（后台前五槽）严格选择完整原句或原段，保留条件、否定、数字及原有编号。没有适当内容则使用唯一且无引用的缺失块：“提供的素材中没有该内容。”。不添加主观评价、拓展推演、素材外知识，也不另列原文对照。

每个原文块恰好绑定一条本 Run 的可定位 PDF 证据。后台复核证据文本与 PDF 版面，定位真实页、段和行；Word 在段落末标注“《文件名》第N页，第N段，第N行”，跨行使用行号范围。页码为 PDF 文件物理页，不是期刊印刷页码。原文摘录不得只取会改变含义的半句话。

## 3. 文献述评

述评允许自主分析，依据只来自前五槽已经摘录的原文。每块可引用多条（最多 20 条）前文依据。页段行标注表示分析的依据位置，不表示该自主分析本身是原文。

| 子模块 | 必须处理的内容 | 块类型标记 |
| --- | --- | --- |
| 已取得的成果 | 总结已证实成果及适用边界，不能将计划或建议当作既有成果 | achievement |
| 文献的不足之处 | 不少于两个相互不同且有依据的学术争议；逐个比较各观点合理性与局限性 | viewpoint_comparison |
| 文献的不足之处 | 每个争议的根本原因，如样本差异、研究设计、理论假设；不确定的原因明确为待验证假设 | root_cause |
| 本文创新点 | 当前争议下的研究空白 | research_gap |
| 本文创新点 | 未来突破方向 | future_direction |
| 本文创新点 | 本文拟开展的创新思路，明确为研究设想，不能声称已完成或首创 | innovation |

同一争议的观点对比与成因使用相同 controversy_number（1—20 整数）。这些字段保存在正文 JSON 中并参与 content_hash。机械覆盖检查只确认角色和编号，不等于学术支持；语义核验会检查观点差异、适用条件、分析依据、假设边界与两个争议是否真实不同。

## 4. 争议证据不足时允许导出

用户已明确选择：允许带“争议证据不足”说明的述评草稿导出。系统保留能支持的内容，不虚构两个争议。缺少两个完整的观点对比与成因分析，或相关块未获得 supported 且结构合法、无问题的核验结论时，在 Word “文献的不足之处”内自动插入不足说明，明确按述评草稿导出。成果、空白、方向或创新分析不足也在该处列出；不另增核心模块。

核验的 needs_review、过时版本等原有警示仍需按现有流程确认；未保存、核验任务未成功或来源结构不合法依旧不能导出。正文不出现“模拟草稿（需人工审阅）：”。

## 5. 实现与历史兼容

- 生成冻结版本：review-gen-v6-source-selection；正文策略：pdf-source-with-commentary-v2。
- 完整原句策略沿用 complete-pdf-passages-v1；定位策略沿用 pdf-geometric-lines-v1；原文选择冻结 pdf-passage-selection-v1，模型仅返回原句编号，后台填入原文，不再向原文模块提供旧分析摘要。
- 核验版本：review-validation-v2-commentary；Word 模板：docx-template-v4-source-commentary。
- 生成三个述评槽使用已生成前文与其原文依据，不从旧分析摘要直接补充事实。每槽最多一次结构/依据修复调用；失败不提交部分正文。
- 前文传入模型时移除临时 block_id，使任务重试能复用同一逻辑调用身份及缓存结果。
- OpenAPI 与模型 JSON Schema 增加 limitations、innovation，以及可选 analysis_role、controversy_number；新块通过服务层按内容槽强制验证这些字段。前端类型由 npm run contracts 生成。
- 历史五节及六槽版本仍可读取、编辑与核验，旧哈希计算保持兼容；新导出必须使用八槽，已有历史 Word 文件仍可按原授权下载。需要新规范时从项目工作区重新生成，不原位改写旧版本。
- 模拟模型不作真实学术争议判断：述评使用缺失说明，由不足提示明确标为草稿。

## 6. 使用步骤

1. 更新代码后启动或重启 Django 和 Celery worker。
2. 进入项目的“04 / 手稿”，从就绪分析快照重新生成综述。
3. 核对原文模块；在述评里编辑“分析内容”与“争议编号”，同一争议的对比和成因配对，引用前文已经使用的证据。
4. 保存新版本并核验，检查待审意见及争议不足提示。
5. 确认需要的警示后导出；Word 就绪后自动下载，正文使用上述固定顺序。
