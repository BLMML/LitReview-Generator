## 原因

旧手稿来自 mock。该模式只匹配少量独立标题，不做真实学术归类，实际 PDF 的摘要、正文常为行内或跨行排版，六个模块因此均返回缺失说明；再次创建相同请求还会复用 mock 缓存。实际证据检索正常，各内容槽能选到十条证据。空白不是九篇 PDF 未解析。

用户又为缺失说明添加引用，违反“缺失说明独占模块且无引用”的保存约定，导致截图中的红色错误。

## 修复

- 前端固定缺失说明文字并关闭其证据选择。改为原文正文时清除占位句；添加正文块会替换单块缺失说明。保存前检查类型、引用数量及模块独占规则。
- 后端新增完整原文候选 `quotable_passages`，从 PDF 字符几何读取完整句段，与对应证据匹配并再次定位，不把超过 600 字符的单句截短。不提供页尾未结束子句；后续页未缩进的首个句段存在跨页风险时只保留后续完整句子。
- 冻结生成版本 `review-gen-v4-source-passages` 与候选策略 `complete-pdf-passages-v1`。每节原文校验失败最多修复一次，修复逻辑调用身份稳定；仍失败给出具体模块及 `MODEL_OUTPUT_INVALID`，不提交空白版本。
- 修正原文定位误判：段首摘要标签和前一句的脚注角标不妨碍后一完整句被选用。普通冒号前的条件仍不能删去，否定、条件和结论的保护保留。正文必须能回到真实 PDF 文字；位置算法不接受模型编造的段行。
- `.env` 与已重启的 Django / Celery worker 使用 real。文档启动命令清除终端旧模式覆盖，统一读取 `.env`。旧 mock 分析和旧手稿仍为历史结果，未冒充重新分析。
