# 论文账本删除功能

日期：2026-10-02。项目：`D:\LitReview Generator`。

## 用户操作

1. 刷新研究工作台，打开“01 / 文献”。
2. 在不需要的论文下点击“删除论文”。
3. 弹窗核对标题，点击“确认删除”；“保留论文”或 Esc 可取消。
4. 成功后该论文移出当前账本并释放项目名额。旧分析提示语料过时，需要重新分析后才能新检索或生成。

任务执行 / 取消期间禁用删除，仍可阅读原文。已有分析、证据、综述和 Word 保留历史引用及原始 PDF；这是逻辑删除，不销毁历史材料。重新上传同一 PDF，或重新导入同一 arXiv 来源，会恢复原记录、原元数据及文件并设为纳入；恢复同样受 30 篇上限限制。

## 实现与契约

- `DELETE /api/v1/papers/{paper_id}`，JSON `{expected_version: 正整数}`，成功 200，统一信封中的 data 为 `{paper_id, deleted:true, corpus_revision}`。
- 强制会话、CSRF 和 owner；越权统一 404，忙碌 409 PROJECT_BUSY，旧版本 409 VERSION_CONFLICT。失败时页面保留论文。
- `Paper.deleted_at` 非空表示删除，数据库约束要求 included=false。删除 / 恢复都递增 Paper.version 与 Project.corpus_revision；重复删除不再次递增。恢复后旧 DELETE 版本不能再次删除。
- 列表、新分析和当前名额统计排除已删除记录。取消纳入但未删除的论文仍占名额。历史详情 / 文件仍通过归属校验读取，已删除记录不可 PATCH。
- 同项目哈希 / arXiv 唯一约束继续覆盖已删除记录，恢复复用同一 ID。旧上传幂等键仅重放冻结响应，不撤销后续删除；恢复需要新提交。
- 编辑 / 删除按 Project → Paper 加锁，恢复也在 Project 锁内发布；后台 arXiv 恢复沿用租约检查。历史 RunPaper 及后续产物不改写。
- OpenAPI 同步新增 PaperDelete / PaperDeletion，目前 44 个操作、41 个公共 Schema；前端生成类型已更新。`00`—`04` 与职责说明同步。

迁移文件：`backend/apps/literature/migrations/0002_paper_soft_delete.py`。页面使用原生 dialog，保持 Anti-Polish / Raw Aesthetic 的纸白、牛皮纸边与深红删除文字；支持焦点恢复、Esc 和手机布局。
