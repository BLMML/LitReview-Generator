# 项目删除：实现与验证

更新日期：2026-10-03。此功能用于从“项目档案”移除整本项目手稿，包括关闭该项目下所有资源的访问入口。

## 用户操作

1. 先下载需要保留的论文或 Word 文件。
2. 在“项目档案”找到项目，点击卡片底部的“删除项目”。
3. 核对弹窗中的项目名称和删除范围，再点击“确认删除项目”。点击“保留项目”或按 Esc 可取消。
4. 删除成功后卡片消失，数量和分页同步更新；刷新后仍保持删除状态。

任务进行中暂时不能删除，应等待任务结束或先在任务账本取消。当前界面不提供恢复项目功能。详细操作见 [用户使用说明书 §4.3](../用户使用说明书.md#43-删除整个项目)。

## 数据与权限

- 使用 `Project.deleted_at` 逻辑删除；只递增项目 `version`，不改写 `corpus_revision` 或历史快照。
- 项目列表不再返回该项目；项目及其论文、PDF、分析、证据、检索、任务、综述、核验、导出与 Word 下载入口均返回 `404 NOT_FOUND`。
- 底层文件、论文、分析、正文版本、导出记录、模型调用与费用账本保留，便于历史核对。内部任务结算仍可读取项目行。
- 重新上传论文不会恢复已删除项目；当前没有公开恢复接口。
- 删除只允许项目所有者操作，仍需会话及 CSRF。重复删除已删除项目返回成功，不重复递增版本。

## 契约与一致性

新增 `DELETE /api/projects/{project_id}`，请求体为：

```json
{
  "expected_version": 1,
  "expected_corpus_revision": 1
}
```

成功响应的 `data` 为：

```json
{
  "project_id": "项目 UUID",
  "deleted": true
}
```

删除事务先锁 `Project` 行，与文献修改及任务受理串行。任务处于 `queued`、`running`、`cancelling` 时返回 `409 PROJECT_BUSY`；项目版本或语料版本变化时返回 `409 VERSION_CONFLICT`，附当前两项版本，要求重新读取后确认。删除后等待同一行锁的修改请求会重新检查删除状态并返回 404。

HTTP 文档、数据模型、文件职责、OpenAPI、生成的 TypeScript 类型和用户说明书已同步。契约现在包含 45 个 HTTP 操作、43 个公共数据结构。

## 界面

保留现有 Anti-Polish / Raw Aesthetic 风格，在每张卡片底部并列显示“打开手稿”和红色“删除项目”。按钮独立于项目链接，不会误触发导航。原生确认弹窗默认聚焦“保留项目”，支持键盘取消、请求期间禁用重复提交和移动端布局。

删除最后一条分页记录时会回到有效页。服务端拒绝删除时保留卡片并显示错误及请求编号，用户可重新读取项目后操作。

打开已删除项目的旧链接时显示“资源不存在或不可用”，请求结束后收起加载提示；旧请求不会清除后来打开的项目的加载状态。

## 本机应用

开发数据库已应用 `projects.0002_project_soft_delete`；该迁移新增可空字段，现有项目保持未删除。Django 开发服务已重新启动，前端开发服务可直接加载新界面。本次验证使用隔离测试数据库，未删除用户现有项目。

## 开发页面旧版本排查

如果出现 `api.deleteProject is not a function`，错误发生在浏览器调用接口之前。当前前端源码和 5173 服务包含该方法；长时间打开的开发页面可能仍持有更新前的 API 对象。点击“重新读取项目”只更新数据，不能替换已经加载的 JavaScript 模块，应按 `Ctrl + F5` 完整刷新页面。

2026-10-03 针对此反馈，在 `resources.ts` 中增加开发环境 API 模块更新后的完整页面刷新，并重启前端服务。复测：22 项前端单元测试、4 项项目删除界面测试及 TypeScript / 构建通过。生产构建不包含开发环境热更新处理。本轮未删除用户的现有项目。
